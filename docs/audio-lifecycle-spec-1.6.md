### AUD-45【修订 v1.1】包络值必须是时间的纯函数

包络的当前值必须可由 `(startValue, target, startMillis, durationMillis)`
与读取时刻唯一确定，并在读取时计算。禁止存在"推进者"这一角色，禁止把
包络的时间演进绑定到任何特定线程的存活或调度。

判据：删除 `advance()` 后，所有消费方（播放线程的 applyGain、tick 线程的
applyMuteToSoundEngineTracks、门控轮询、探针）读到的值仍然正确。

理由（记录用）：v1.4 的"current 只能由播放线程写"默认了播放线程恒存在。
当只有内置声源腿在发声时该线程不存在，MUTE_ENV 冻结，静音在两个方向上
都可能永久失效。

### AUD-49 #6【新增】门控与起播的顺序契约

在同一 tick 内，调用方排入门控成功后，必须立即结束该腿本 tick 的处理，
不得再创建、起播或替换任何声源。新声源的创建只能发生在门控的 action
执行之后的 tick。

推论：任何"排门控"的辅助方法必须向调用方报告"本 tick 是否已排入门控"，
调用方据此提前返回。

判据：grep 每一处 `gatedTransition(` 调用，其后到方法返回之间不得出现
声源创建或 `play()`。

### AUD-49 #2【修订】超时路径与正常路径同构

超时兜底除了日志与"无条件执行 action"之外，其复位行为必须与正常完成
路径完全一致（声源存在 → 按 fadeInMillis 淡入；不存在 → 登记待起播淡入
时长）。禁止以 0ms 时长把包络拉回 1.0。

### AUD-48【修订 v1.2】拆链的待办状态必须显式

1. "待拆链"必须由独立布尔标志表示，禁止用集合是否为空、引用是否为 null
   等哨兵值间接表达。
2. 淡出期间 `active` 不得改变；比较"目标配置是否变化"时，参照系必须是
   淡出的目标态而非当前态。
3. 必须存在取消路径：淡出未完成时若激活条件重新成立，直接取消待拆链并
   将 mix 目标拉回 1.0，不得等待拆链完成后重建。
4. `deactivate()` 与 `tick()` 的停用走同一条门控路径。
